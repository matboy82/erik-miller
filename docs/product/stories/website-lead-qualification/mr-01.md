## Outcome

As Matt and Erik, we can review progress at a persistent test URL and inspect proposed changes through PR previews, with checks completing before deployment.

## Acceptance criteria

1. A fresh checkout on Node 24+ installs from the lockfile and completes the repository's aggregate checks and mobile Lighthouse checks. Evidence records actual command results and the tested revision.
2. With test deployment enabled and authorized, a passing `main` CI run publishes the draft site to the isolated Cloudflare test Pages project and deploys the health Worker. A failed verification job prevents deployment; disabling test deployments permits checks without publishing.
3. The resulting site URL and Worker URL are recorded. The site is reachable, and the Worker's `/health` returns HTTP 200. A local build alone does not satisfy this criterion.
4. An authorized same-repository PR receives a distinct Pages preview after successful checks. Fork PRs run verification without receiving deployment secrets or publishing previews.
5. The persistent site and PR previews remain noindex through HTML, robots rules, and response headers. They do not use the production business domain.
6. The setup guide identifies required secret/variable names and where Matt supplies them. Secret values are absent from source, built client assets, and recorded evidence. Infrastructure placeholders close only after the corresponding live evidence is captured.

## Dependencies and constraints

Cloudflare and GitHub accounts exist. Matt supplies the intended repository/account/project configuration and restricted CI secrets using the [setup guide](../../../operations/cloudflare-test.md). Push/deployment authorization is needed when performing those actions; story approval does not grant it. Preserve user-owned work and the existing health scaffold.

Mobile performance, accessibility, and best-practices scores must each be ≥ 90, with LCP < 2.5 seconds. Preview SEO remains a warning while noindex is intentional; production SEO is a later release criterion.

## Out of scope

Production deployment, DNS changes, intake endpoints, JobTread integration, account creation, final brand selection, and closure of unrelated placeholders.

## Verification notes

QA should cover enabled/disabled deployment, failed checks, main deployment, same-repository PR preview, fork-secret isolation, live health/noindex behavior, and secret isolation. Capture remote CI and live HTTP evidence separately from local checks.
