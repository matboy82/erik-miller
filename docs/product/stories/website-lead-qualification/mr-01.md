## Outcome

As Matt and Erik, we can review progress at a persistent test URL and inspect proposed changes through PR previews, with GitHub verification and Cloudflare build/deployment results recorded separately.

## Acceptance criteria

1. A fresh checkout on Node 24+ installs from the lockfile and completes the repository's aggregate checks and mobile Lighthouse checks. Evidence records actual command results and the tested revision.
2. A main push triggers separate Cloudflare builds for the draft Pages site and health Worker. Each app publishes after its own build succeeds. GitHub verification runs independently and does not gate publication. No deployment enable flag or GitHub Cloudflare credentials are required.
3. The resulting site URL and Worker URL are recorded. The site is reachable, and the Worker's `/health` returns HTTP 200. A local build alone does not satisfy this criterion.
4. Trusted preview branches receive distinct Pages previews through Cloudflare. Restrict Pages preview branches and disable non-main Worker builds. Fork PRs receive GitHub verification without deployment credentials; record Cloudflare preview restrictions separately.
5. The persistent site and PR previews remain noindex through HTML, robots rules, and response headers. They do not use the production business domain.
6. The setup guide identifies required secret/variable names and where Matt supplies them. Secret values are absent from source, built client assets, and recorded evidence. Infrastructure placeholders close only after the corresponding live evidence is captured.

## Dependencies and constraints

Cloudflare and GitHub accounts exist. Matt supplies the intended repository/account/project configuration and Cloudflare build settings using the [setup guide](../../../operations/cloudflare-test.md). Push/deployment authorization is needed when performing those actions; story approval does not grant it. Preserve user-owned work and the existing health scaffold.

Mobile performance, accessibility, and best-practices scores must each be ≥ 90, with LCP < 2.5 seconds. Preview SEO remains a warning while noindex is intentional; production SEO is a later release criterion.

## Out of scope

Production deployment, DNS changes, intake endpoints, JobTread integration, account creation, final brand selection, and closure of unrelated placeholders.

## Verification notes

QA should cover independent GitHub verification, successful and failed Cloudflare builds, main deployment, trusted branch previews, preview restrictions, live health/noindex behavior, and secret isolation. Capture remote CI and live HTTP evidence separately from local checks.
