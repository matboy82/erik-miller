# MR-09: Capture and publish approved project stories

**Status**: Approved
**Approval recorded**: Matt, 2026-10-02 (user: "all approved").

**Next phase**: Technical spec/work packages drafted; human approval required before implementation.

## Outcome

As Erik, I can prepare and approve a project story from my phone with little effort, then publish it as accurate, useful proof on the website.

## Acceptance criteria

1. A project entry captures scope, challenges, results, before/after photos, optional finished video, project type, location, and a relevant review link.
2. Erik can prepare an entry from a phone without editing code and inspect an access-restricted, rendered site preview before publishing; a timed walkthrough completes in under 15 minutes.
3. Erik's explicit **Publish** action after reviewing that exact preview approves the content and triggers automatic rebuild/deployment. The content workflow creates no PR and requires no separate Matt/BIS approval. Edits after approval return the entry to Draft.
4. Published entries display accessible media and factual text, appropriate project/service tags, and the review cross-link. Draft substitutes remain visibly labeled and are excluded from production.
5. The system records authenticated Erik identity, time, preview revision, exact content/media hashes, provenance, usage permission, and the approval event. An edit or changed asset invalidates the prior approval.
