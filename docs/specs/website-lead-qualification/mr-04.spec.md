## Probe contract and dependency direction

Implement one cohesive owner under `scripts/jobtread-verification.mjs`, with an opt-in CLI entry. Its caller-visible seam accepts a scenario, validated operation plan, injected transport and runtime credential provider; it returns a sanitized scenario result. CLI parsing and official request encoding stay with that owner. Tests exercise this boundary with local transport doubles; they never replace the outcome being proved. Use native Node capabilities and existing `node:test`; no new SDK, browser framework or service dependency.

Default invocation performs local plan validation only, without requesting credentials or network access. Live scenario dispatch requires explicit live mode, a complete Matt-approved plan and matching boundary. This recorded authorization is an operator control, not independent authentication. Local tooling loads `JOBTREAD_API_URL` and `JOBTREAD_API_KEY` from Matt's ignored `.env`, using Node's `--env-file=.env`; do not copy values into CLI arguments, tracked files, fixtures or generated output. Default/fork CI must never execute live mode or receive a JobTread credential. For a later approved deployment, Matt supplies corresponding server-side Cloudflare configuration and stores the key as a secret; this story changes no Cloudflare settings.

Validate exact documented API/upload destinations. Send credentials only where the official authentication contract requires them; never forward them to upload/download hosts or through unexpected redirects. Signed upload/download URLs are sensitive and must not be logged. Use documented upload stages and headers without guessing a presigned-URL implementation. Fetch only approved synthetic records; no broad customer inventory or private-photo queries.

Each result contains scenario/run alias, evidence kind (`Documentation`, `Live`, `Simulation`, `Owner-confirmed`, `Unverified`), capability status (`Verified`, `Unsupported`, `Unverified`), safe check outcomes, stage/error category, source reference, limits, recovery notes and cleanup outcome. Persist only an allowlisted projection; never serialize request/response bodies, vendor error text, headers, credentials, URLs containing tokens, or unrecognized fields. In-memory returned IDs may drive the next operation; the report uses aliases and relationship/value equality checks.

The probe has no automatic write retries. A timeout or connection loss after dispatch is an ambiguous outcome: stop, inspect the approved synthetic boundary and reconcile before any operator-authorized repeat. A local inventory supports this bounded investigation only; it is not a durable lead store or idempotency guarantee.
