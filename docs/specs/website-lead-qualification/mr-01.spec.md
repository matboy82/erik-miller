## CI and deployment contract

GitHub Actions runs verification on main pushes and pull requests with read-only permissions, no Cloudflare secrets, and no publication job. Retain npm ci, npm run check, and npm run lighthouse. Fork contributions receive these checks without privileged PR-target execution.

Cloudflare owns publication through two projects connected to the same GitHub repository. Both use repository-root installation and Node 24+. Pages uses npm run build:web, SITE_BUILD=review, output apps/web/dist, and main as the persistent test branch. Workers Builds uses npm run build:worker and npx --no-install wrangler deploy --config apps/worker/wrangler.jsonc. The Worker name is erik-miller. Configure Worker builds for main only; restrict Pages previews to trusted branches.

GitHub Cloudflare secrets, environment test, and project/enable variables are no longer used. Workers Builds manages its deployment token in Cloudflare. GitHub checks and Cloudflare builds run independently: failed GitHub verification does not automatically block Cloudflare publication. Each app's failed Cloudflare build prevents that app's new publication; the two resources deploy independently and are not atomic.

The former publication planner and uploader are removed. scripts/test-deployment.mjs retains read-only artifact and HTTP helpers used by local tests; it is not a publication command or automatic post-deploy check. Numbered PR names, current-main API guards, publication credential scanning, and GitHub deployment summaries no longer apply. Record actual Cloudflare deployment revisions, returned URLs, build results, and live noindex/health evidence before claiming readiness.

## HTTP and secret boundaries

Keep HTML robots meta, `robots.txt` disallow, and Pages `_headers` noindex for review builds. Check actual persistent and preview HTTPS URLs after publication; no business-domain attachment is permitted. Noindex is indexing policy, not access control: the test scaffold must contain no private stakeholder or customer material.

Preserve `worker.fetch(Request)` behavior: GET `/health` returns HTTP 200 and the existing scaffold JSON with `Cache-Control: no-store`; HEAD has no body, unsupported methods return 405, and unknown routes remain 404. No database, runtime credential, or new endpoint is introduced.

Keep Cloudflare credentials and lead PII out of source, fixtures, client output, and retained logs. Use harmless sentinels to prove client-bundle isolation and inspect the complete output tree. Do not print real secret values to test masking. Configuration names and redacted outcomes are sufficient evidence.

## Required quality bar and verification

Pin the approved QA mobile protocol, 2026-10-01 branding kit, candidate revision/dirty diff, lockfile, and Lighthouse config. Existing three-run mobile LHCI measures review `/` starting at A. Preserve its current optimistic aggregation and make that setting explicit: category assertions use the best score; LCP uses the minimum numeric value across the three valid runs. Scores must be ≥ 0.90 for performance, accessibility, and best practices; SEO stays warning-only.

Aggregation follows the installed `@lhci/utils` assertion behavior and [official LHCI configuration reference](https://googlechrome.github.io/lighthouse-ci/docs/configuration.html), read 2026-10-01. Record all individual results so the aggregation does not hide variability.

Keep the existing LHCI LCP assertion and add a strict report check to `npm run lighthouse`: the same aggregated LCP must be finite and **< 2500 ms**. Equality fails. Require three valid reports for the expected page; missing, malformed, wrong-page, or incomplete reports fail rather than silently passing. Retain individual reports, assertion output, and the strict result. Test values below, equal to, and above 2500 independently of browser variability. No new browser framework or public measurement interface is selected.
