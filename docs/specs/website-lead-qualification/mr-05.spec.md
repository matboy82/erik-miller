## Intended change and boundaries

Add a reviewable local website experience and a general inquiry API that validates a bounded request, durably accepts it, and delivers a general-inquiry customer/job record to JobTread. Use the existing static Astro site and health Worker. The local preview uses synthetic read-only sample values and local-only outcome simulations; it does not submit, store, or accept real lead data. The API response may claim receipt only after durable acceptance. Preserve JobTread as system of record; local intake state is a short-lived delivery ledger, not CRM search or customer master data.

`POST /intake/contact` accepts a name (1–120 characters), exactly one email (up to 254 characters) or phone (up to 32 characters), and a message (1–5,000 characters); the normalized request body is limited to 8 KiB. The client generates an opaque UUID idempotency key for a new inquiry and reuses it for retries; the Worker enforces uniqueness and returns the original safe receipt. It returns `accepted` only after D1 commit and queue enqueue succeed. Invalid requests return field-safe validation errors and never dispatch.

For local/demo review, use clearly labeled test copy derived from this field outline: “Tell us about your project”; “Your name”; “Email or phone”; “How can we reach you?”; “What would you like help with?”; submit label “Send inquiry”; validation prompt “Add your name, one way to reach you, and a message”; demo confirmation “Thanks — your test inquiry was received.” This copy is synthetic and not Erik-approved. Erik's approval gates real customer use and live intake, not implementation or local review. No real lead PII may be collected by a demo.

The protected operator boundary reports only receipt alias/state/timestamps/error category and permits retry/reconciliation; it never reads or returns raw payloads. Require a valid Cloudflare Access JWT and an email claim matching a fail-closed allowlist configured for Erik and Matt. The allowlist remains empty until account configuration. Keep the operator boundary unavailable until that policy and Access application are configured.

The documented JobTread delivery sequence is customer → location → contact → job. Store the contact method in an existing Contact custom field selected by runtime field ID; no JobTread schema/custom-field creation is included. Use the receipt alias in record names for operator reconciliation. Retrieve the Contact custom-field value and the Job → Location → Customer link before marking delivery complete. Each write is checkpointed; an ambiguous write stops for operator readback and is never retried blindly. Runtime configuration and live account behavior remain unverified until the separately approved synthetic operation plan runs.

## Data, security, and compatibility

Accepted 0006 governs D1 outbox/idempotency, Queues delivery, and private R2 staging if photos are later accepted. Deliver only opaque IDs through the queue. Validate and normalize input server-side; use least-privilege JobTread credentials from Cloudflare secrets; allowlist logged fields; no lead payload, credentials, uploaded photo bytes, signed URL, or vendor response in logs/client output. Intake is disabled unless `INTAKE_ENABLED=true`; leave it unset until live-use gates are satisfied. Retain payloads for seven days after verified delivery, then delete them; retain only non-payload receipt metadata for 90 days. For undelivered submissions, alert the operators at 24 hours and on DLQ entry; retain payloads for at most 30 days after acceptance, then delete and retain a payload-free failure tombstone for 90 days. Cleanup failures alert operators and remain visible as failures. Before live submissions, configure Erik and Matt's individual Cloudflare Access identities and account-level Cloudflare notifications to both; confirm alert delivery and cleanup behavior. No production PII is collected until these controls and the exact JobTread operation plan are approved.

Keep the health route behavior and existing package pins. Introduce an OpenAPI contract and explicitly version its fields/errors. No browser-to-JobTread request, CRM replica, provider substitution, or generic export/search endpoint.
