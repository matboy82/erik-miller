**Approval question**: Approve this development/test versus release-only boundary. This does not record Erik's brand choice or authorize production.

## Purpose and boundary

This spec lets development and review evidence be completed using the approved draft directions while preserving Erik's live brand decision and production artifact as later gates. `$sdd-release` remains a separate rollout plan.

## Development/test exit

- Implement the A/B/C theme and copy controls, persistence/fallback behavior, draft labels, and production isolation contract.
- Complete all required B1/B2 keyboard, touch, focus, contrast, responsive and zoom checks for each direction and longest copy; screenshots or automated scores alone do not close manual checks.
- Verify controlled production builds for A, B, and C, proving one selected set and no review controls, switching/persistence code, or alternate tokens; prove missing/invalid locks fail safely.
- Resolve the current Block review findings and obtain required independent reviews. These development/test checks cannot be deferred.

## Release-only gates

| Gate | Owner/evidence |
|---|---|
| Erik selects the final direction, tagline, and copy; record the matching brand lock and ADR | Erik decision record and accepted ADR |
| Build and inspect the actual selected production artifact after the brand lock | Matt/BIS artifact and isolation evidence |
| Approve release plan and any rollout action | Matt; separate explicit authorization |

## Acceptance disposition

| Story acceptance | Development/test proof | Release-only proof |
|---|---|---|
| AC1-2 | All draft variants, controls, transitions, persistence and fallback verified | None |
| AC3 | Required keyboard/touch/mobile/WCAG 2.1 AA checks | None |
| AC4 | Draft/factual-status labeling verified across variants | None |
| AC5 | Controlled A/B/C production isolation and invalid-lock rejection | Erik's actual choice/lock and selected production artifact |
| AC6 | Controlled builds do not create an approval or alter the real lock | None |

Only this spec's approved, named brand decision and production artifact checks may be `Deferred to release`; a missing manual check or broken control remains a development blocker. Deferral does not mean Erik approved a direction or that the story is accepted.

## Handoff

After all development/test checks and required independent reviews pass, `$sdd-release` prepares the rollout plan. Erik's decision and production artifact must be recorded before release readiness; deployment remains separately authorized.
