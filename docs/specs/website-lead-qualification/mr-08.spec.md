## Intended change and interfaces

Place Erik's Google Calendar Appointment Schedule page after the qualified wizard result; link to the exact owner-managed page and state the configured mode (phone or in-person). Google Calendar owns schedule availability and confirmed booking events. Erik can update mode and availability in his Workspace without a code change. Do not add Calendly, web conferencing, or a custom booking engine.

Before production, verify the Workspace subscription/entitlements, calendar conflict checks, buffers, timezone, confirmation/reminder, cancellation/reschedule behavior, and supported JobTread association. Google supports a booking page and calendar event, but this ADR does not select an integration API or association method. Determine whether the supported JobTread boundary and a separately approved Google calendar integration can associate the appointment to the right customer/job. If not, keep this acceptance criterion blocked and return for an explicit product amendment; do not silently substitute Calendly, Zapier/Make, a custom scheduling system, or unsafe manual matching.

## Security, verification, and rollout

Google account credentials are not placed in the public website. Prefer a link or the owner-approved Google embed after accessible browser review. Minimize booking form fields and do not copy attendee PII into public assets/logs. If a server-side calendar/JobTread integration is selected after verification, it needs its own scoped authorization, token storage, event deduplication, retention contract, and Proposed ADR if it creates a new durable cross-service boundary.

Use browser checks for the schedule link/embed, accessible handoff, mode/copy, and qualified-only entry. External QA B1 covers account availability, DST, buffers, conflicts, Google confirmation/reminders, cancel/reschedule, and JobTread association using separately authorized synthetic accounts. Run `npm run check` and deployment dry-run; no account setup or deploy. If a later approved sync contract exists, its tests must cover duplicate events, ambiguous writes, privacy, and reconciliation. Rollback hides the booking entry point and preserves unresolved association records.
