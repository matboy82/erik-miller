## Intended change and boundaries

Add a mobile-first authenticated entry form for portfolio content. The proposed Access-protected Worker validates a typed payload/media and stages a content-only preview branch through a narrowly scoped GitHub App. Cloudflare builds a restricted noindex preview. Erik reviews the actual rendered entry and selects **Publish**; the service records the exact preview revision/content/media hashes and Erik's authenticated approval, then commits only those validated content/approval files directly to the production branch. This content flow creates no PR. Existing Astro Content Layer records remain the only published content source.

Capture scope, challenge, result, project type/location, before/after images and optional video reference, review cross-link, factual sources, licensing/provenance and alt text. Restrict repository/path/ref operations, reject oversized/unsafe media and content, and scan/redact metadata. Validate through the same schema used by the site; keep content separate from layout.

## Security and verification

Cloudflare Access identifies Erik; the app must validate the Access assertion and GitHub App credentials remain server-side. Limit GitHub writes to the one repository and approved content/media/approval paths; permit the content publisher to write directly to the production branch only through this service. It cannot merge code, edit workflow/configuration files, change brand locks, alter unrelated placeholders, or write arbitrary paths. Normal engineering PR/review workflows remain unchanged. Audit preview, approval, commit and deployment identities/revisions without logging private content or credentials.

Test the form through the user-visible boundary, schema/size/path rules through unit tests, and GitHub/Cloudflare through explicit external boundaries. The phone walkthrough must be under 15 minutes. Verify that the preview is the exact revision later published; changing any bytes invalidates approval. QA P1 covers preview access, Erik's owner-only approval, no-PR commit path, build failure, provenance and production exclusion. Run `npm run check` and inspect the complete production output. No repository integration/account configuration occurs before separate authorization.

Rollback disables the authoring route; unapproved preview branches can be removed after inventory. Never remove published records/media as part of code rollback. Restore a published entry through its recorded version and the same Erik approval path. **ADR**: Accepted 0008 governs auth, preview, direct publishing and deployment. **Done**: access/permissions, mobile duration, exact revision/hash binding, automatic build outcome, production gates, runbook and tests all pass.

**Implementation gate**: Follow Accepted 0008 and the listed account, access, and production prerequisites.
