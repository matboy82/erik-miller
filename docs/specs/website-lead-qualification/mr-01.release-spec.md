## Purpose and boundary

This artifact separates local implementation and test exit from evidence that requires trusted remote infrastructure. It does not change the approved story, review findings, deployment architecture, or later `$sdd-release` rollout plan.

## Development/test exit

- Complete the approved fix scope and selected implementation packages; keep the existing Block review verdict in force until its findings are resolved and reviewed again.
- Run `npm ci`, `npm run check`, and `npm run lighthouse` from an isolated fresh checkout of the final candidate and record exact revision, commands, versions, and results.
- Verify configuration generation, secret isolation, noindex HTML/robots/header rules, app build failure behavior, and Worker main-only/Pages preview restrictions with local deterministic checks or simulations where possible.
- Complete review-required local and manual checks. Missing local evidence or implementation remains a development blocker.

## Release-only gates

| Gate | Owner/evidence |
|---|---|
| Verify independent Cloudflare Pages and Worker builds on main, publication after each app succeeds, and actual live site/health URLs | Matt/BIS authorized configuration and sanitized Cloudflare run plus HTTP evidence |
| Verify trusted Pages branch previews and configured preview restrictions; confirm fork PR verification needs no deploy credentials | Matt/BIS configuration evidence and sanitized run record |
| Verify live response noindex and production-domain separation; close only infrastructure placeholders whose exact conditions pass | Matt/BIS live HTTP/config evidence and placeholder update |
| Approve release plan and any rollout action | Matt; separate explicit authorization |

## Acceptance disposition

| Story acceptance | Development/test proof | Release-only proof |
|---|---|---|
| AC1 | Isolated fresh-checkout install, aggregate checks, mobile Lighthouse | None |
| AC2 | Build/config and failure-isolation simulations | Independent live main app builds and publication behavior |
| AC3 | Local health/noindex response checks | Reachable deployed URLs and live `/health` 200 |
| AC4 | Configuration/secret-boundary checks | Trusted branch preview and remote restrictions |
| AC5-6 | Artifact, robots, header configuration and secret-isolation checks | Live header/URL evidence and final infrastructure placeholder closure |

Only an approved spec may classify named live checks as `Deferred to release`. Deferral does not clear the current Block verdict, waive the fresh-checkout checks, or establish story acceptance or release readiness.

## Handoff

After development/test evidence and required independent code/adversarial reviews are complete, `$sdd-release` prepares the rollout plan. Cloudflare/GitHub mutations, pushes, deployment, production, and DNS actions require separate authorization.
