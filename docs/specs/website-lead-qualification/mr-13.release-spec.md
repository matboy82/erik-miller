# MR-13 Operational handover: Release Specification

**Status**: Draft
**Work item**: MR-13
**Inputs**: [Story](../../product/stories/website-lead-qualification/mr-13.md), [developer spec](mr-13.spec.md), [work packages](mr-13.work-packages.md), and [QA plan](../../qa/test-plans/website-lead-qualification.testplan.md).
**Approval question**: Approve the development/test versus release-only boundary below. This does not approve deployment, account changes, or external actions.

## Purpose and boundary

This spec separates evidence needed to finish implementation and testing from evidence needed for release. A deferred release gate does not mark the story accepted or make release ready. The later `$sdd-release` plan remains required, and you authorize any rollout separately.

## Development/test exit

Draft role-based runbooks and a traceable checklist from approved technical, QA, review and operational artifacts. Verify links, commands, owners as known, sensitive-data handling and rollback steps; unknown live facts remain explicitly marked.

Implementation and code review may finish only when every item above is implemented and verified. Use deterministic local tests and clearly labeled simulations for unavailable external boundaries. Missing code, missing owner decisions that define product behavior, or unrun local quality checks remain development blockers.

## Release-only gates

Erik and Matt complete the applicable operator walkthroughs; verify live environment/contacts/observability, recovery and rollback rehearsal, sanitized live inquiry evidence when separately authorized, all upstream story approvals and the concrete story-specific release plan. Testimonial evidence/rights stay separate and require exact approval.

## Acceptance disposition

| AC | Development/test | Release-only |
|---|---|---|
| AC1-4 | Runbook/checklist consistency and link/command checks | Operator walkthrough and environment/recovery evidence |
| AC5-6 | Documented release and rollback procedure | Approved rollout plan, authorized live proof and any exact testimonial rights |

`Deferred to release` applies only after this release spec is approved, and only to the release-only evidence listed above. It does not waive local tests, security controls, required quality bars, or product behavior that can be implemented and tested before rollout.

## Handoff

After development/test evidence and the required independent review verdicts are complete, `$sdd-release` creates the separate release plan and marks readiness. External writes, production deployment, DNS/account changes, and public communications require their own explicit authorization.
